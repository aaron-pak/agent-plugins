## The `artifact` server

Claude Code pairs these skills with its Artifact tool and checks pages with `ArtifactCheck`. The plugin's `artifact` MCP server (`mcp/server.mjs`, bundled from `src/`) stands in for both, and `scripts/publish.mjs` and `scripts/preview.mjs` do the same from the shell where the server isn't connected.

What it takes from Claude Code:

- **Tool text.** The tool description is adapted from the Artifact tool's, including the rule that a new artifact starts with a `quickstart` call and its full name, and the `quickstart` result matches Claude Code's for an account without Artifact types. Claude Code cuts an MCP tool's description at 2,048 characters and defers MCP tools behind tool search, so the server sends the first paragraph as the tool description and the rest, in order, as its input schema's description, and asks Claude Code to load the tool up front, as its own Artifact tool is.
- **Publishing.** `publish` wraps the page in the claude.ai skeleton, adds the Mermaid runtime Claude Code adds to a page with diagrams (the same Mermaid 11.16.1 build, loaded from jsDelivr instead of claude.ai) and the highlight.js runtime it inlines in a page with a language-tagged code block (`scripts/hljs-runtime.html`, verbatim), and writes the page to `~/artifacts` (or `ARTIFACTS_DIR`). It unwraps only a skeleton it or claude.ai added, keeping its `lang` and safe-area choice; any other full HTML document goes inside the skeleton as it is. The page's name is the first `<title>` in 8,192 characters, ignoring any after an `<svg>`. Like the Artifact tool's file-to-artifact map, which lasts one session, publishing the same path again updates the same artifact only within one server process; a later session's publish makes a new artifact and names the earlier one.
- **Markdown.** A Markdown file is rendered with marked 16.1.0 (GitHub-flavored, ```` ```mermaid ```` fences as diagrams) into Claude Code's plan template (`scripts/markdown-template.html`, verbatim), with the eyebrow "Markdown · <file>", the file name as the tab title and the opening heading as the page heading, by the same rules as the CLI.
- **Preview.** `preview` renders a page with `ArtifactCheck`'s widths, themes, content policy, step timeouts, checks and report, and returns captures sized as `ArtifactCheck` sizes them. It loads only the page, its Mermaid runtime and Google Fonts, so CDN scripts are reported as blocked and the page's own files are listed in a note, and it declines a Markdown file in `ArtifactCheck`'s words.

Where a local machine can't do what claude.ai does, it differs:

- **The link** is a `file://` page on this machine, so the publish result says to share the published `index.html` (not the source file), and says when the page was not opened. Because of that link, the description's supporting-files paragraph and the skill's page contract say what such a page can't do with its own files (`fetch()`, module scripts, Workers, canvas export) and that local pages may share one storage origin.
- **The page** carries a Content-Security-Policy meta that mirrors the viewer: Claude Code's own model of it (its preview's policy) plus the five script CDNs the page contract allows, without that policy's `webrtc 'block'`, which Chromium logs as an error on every load. The Mermaid runtime is skipped for a page that loads Mermaid itself with a `<script src>`. A file that was a full HTML document gets a note asking for page content only next time, and `read` returns the page without its skeleton and says publishing adds it.
- **Inputs.** Paths must be absolute, because Codex starts the server in the plugin's folder. Links are accepted percent-encoded or not, as a folder or as its `index.html`. An unknown parameter is refused by name, and supporting files are all checked before anything is written.
- **The artifacts folder.** Publishing a page from inside it updates that artifact, a new artifact never takes a folder that is already on disk, and an unreadable `index.json` is set aside and rebuilt from the artifact folders.
- **Drafts.** Claude Code lists a scratchpad only when its own Artifact tool is on, so when a session has no scratchpad, the description and the `quickstart` result send page files to a private drafts folder per session in the system temp directory, and a `PreToolUse` hook (`hooks/allow-drafts.mjs`) approves writes inside it the way Claude Code approves its scratchpad.
- **Preview.** It is offered only when a startup check finds Playwright and a Chromium, and `ARTIFACT_PREVIEW=0` turns it off. It finds Playwright beside the script or installed globally, never in the project (the startup check would otherwise run the project's code), launches Playwright's full Chromium or an installed browser from Claude Code's own list when Playwright's headless browser is missing, and resizes captures in that browser instead of with `sharp`. It also runs two checks `ArtifactCheck` lacks, for layout bugs that test pages from both tools shipped: running text that a grid or flex parent splits into separate rows or columns, and an SVG whose labels draw too small to read at phone width (under 7.5 px).
- **Codex.** Codex shows at most 1,000 bytes of a plugin MCP tool's description and drops every description from an input schema over 5,000 bytes, so when the client is Codex the server sends a compact tool with the lead, the first-call rule, the calls and the page contract's essentials, and leaves the rest to `quickstart`.
